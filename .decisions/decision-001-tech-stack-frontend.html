Technisch

Die Basis-Entscheidung: Womit bauen wir die UI? Du brauchst ein responsives Dashboard, Galerie-Views, Formulare, Modals und ein Dashboard mit Charts. Alles läuft in Docker, also SSR ist nice-to-have aber kein Muss. Wichtig: schnelle Entwicklung, gute Component-Library-Anbindung und einfache Wartbarkeit.

Das größte Ökosystem. React + Vite ist schnell im Dev, Tailwind gibt dir maximale Flexibilität beim Styling. shadcn/ui liefert hochwertige, kopierbare Komponenten für Tables, Modals, Forms. Recharts für Dashboard-Charts. Riesige Community, jedes Problem ist gelöst.

Funktioniert gut wenn

  • Du maximale Flexibilität willst
  • Du React-Erfahrung hast
  • Viele 3rd-Party-Libs brauchst

Achtung bei

  • Mehr Boilerplate als Next.js
  • Routing muss manuell (React Router)
  • Kein SSR out of the box

Next.js als Fullstack-Lösung: Frontend UND Backend in einem Projekt. API Routes oder Server Actions ersetzen ein separates Backend. Tailwind + shadcn/ui für die UI. Prisma als ORM direkt angebunden. Ein Docker-Container für alles. Weniger Moving Parts, schnellere Entwicklung.

Funktioniert gut wenn

  • Du alles in einem Projekt willst
  • Kein separates Backend nötig
  • Schnelles MVP wichtig ist
  • File-based Routing spart Setup

Achtung bei

  • Next.js-spezifische Patterns lernen
  • Docker-Image etwas größer
  • Overkill wenn reines SPA reicht

Vue 3 mit Nuxt als Fullstack-Framework. Ähnliches Konzept wie Next.js, aber im Vue-Ökosystem. Nuxt UI ist eine solide Komponentenbibliothek. Vue's Composition API ist clean und intuitiv. Gute Option wenn du Vue bevorzugst. Etwas kleineres Ökosystem als React, aber alles da was du brauchst.

Funktioniert gut wenn

  • Du Vue bevorzugst/kennst
  • Nuxt UI spart viel Arbeit
  • Einsteigerfreundlicher als React

Achtung bei

  • Weniger 3rd-Party-Libs als React
  • Kleinere Community für Edge Cases
  • Nuxt 3 hat noch einige Rough Edges

SvelteKit ist das performanteste Framework mit dem geringsten Boilerplate. Kein Virtual DOM, kompiliert zu vanilla JS. Fullstack-fähig mit Server Routes. Svelte 5 Runes sind elegant. Nachteil: deutlich kleinstes Ökosystem, weniger fertige Komponenten, OCR/Chart-Libs dünner. Für ein Solo-Projekt ein Risiko.

Funktioniert gut wenn

  • Performance oberste Prio ist
  • Du minimalen Code willst
  • Lust auf modernes Framework

Achtung bei

  • Kleinstes Ökosystem der 4
  • Weniger fertige UI-Komponenten
  • AI-Coding-Support schwächer

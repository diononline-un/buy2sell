Label-PDF-Generation

Technisch

Du willst pro Haul ein PDF mit Labels (4x8 Inch) generieren, die eine Unique-ID pro Artikel enthalten. Diese Labels klebst du auf deine voreingepackten Artikel. Frage: Wie generieren wir das PDF und was steht auf dem Label?

@react-pdf/renderer generiert PDFs server-side in deiner API Route. Du definierst das Label-Layout als React-Komponenten (JSX), generierst QR-Codes mit der qrcode-Library, und streamst das PDF als Download. Gleiche Sprache (React/JSX) wie dein Frontend. Labels: QR-Code (scannbar → öffnet Artikel in der App), ID, Kurzname, Variante.

Funktioniert gut wenn

  • React-Syntax für PDF-Layout
  • Kein externer Service
  • QR-Codes → scannbar in App
  • Server-side = schnell

Achtung bei

  • Exakte mm-Positionierung fummelig
  • Font-Embedding nötig

Du baust die Labels als HTML/CSS-Template, Puppeteer rendert sie in einem Headless Chrome zu einem pixelgenauen PDF. Volle CSS-Power (Flexbox, Grid, @page, @media print). Nachteil: Puppeteer ist eine fette Dependency (~300MB Chrome), braucht mehr RAM im Docker-Container, und ist langsamer.

Funktioniert gut wenn

  • Volle CSS-Power für Layout
  • Pixelgenaue Positionierung
  • Bekannte Technologie (HTML/CSS)

Achtung bei

  • ~300MB Chrome im Container
  • Langsamer als react-pdf
  • Mehr RAM-Verbrauch
  • Docker-Setup aufwendiger

PDF wird komplett im Browser generiert mit jsPDF. Kein Server-Call nötig, Daten kommen aus dem State. Schnell für kleine PDFs. Aber: jsPDF hat ein Low-Level-API (Koordinaten in mm), kein JSX, kein CSS. Für ein Grid aus Labels viel manuelle Positionierung. Fragil bei Layout-Änderungen.

Funktioniert gut wenn

  • Kein Server-Call nötig
  • Schnell und leichtgewichtig
  • Kein Backend-Dependency

Achtung bei

  • Low-Level-API (mm-Koordinaten)
  • Kein CSS, kein JSX
  • Layout-Änderungen fragil
  • Font-Support eingeschränkt

PDFKit ist die Low-Level Node.js PDF-Library. Sehr leichtgewichtig, keine externen Dependencies. Aber wie jsPDF: Du arbeitest mit Koordinaten (x, y, width, height), kein deklaratives Layout. Solide für einfache Dokumente, für ein Label-Grid mit QR-Codes und Text aber mehr Aufwand als react-pdf.

Funktioniert gut wenn

  • Minimal, keine große Dependency
  • Server-side, schnell
  • Volle Kontrolle über jeden Pixel

Achtung bei

  • Imperatives API (Koordinaten)
  • Mehr Code als react-pdf
  • Layout-Änderungen aufwendig

Datenbank

Technisch

Du nutzt Prisma als ORM — jetzt brauchen wir die Datenbank dahinter. Dein Use Case: Artikel mit Bildern, Hauls/Batches, Versandkosten-Verteilung, Verkaufspreise, berechnete Felder. Alles self-hosted in Docker. Kein extremes Datenvolumen, aber relationale Beziehungen (Haul → Artikel, Artikel → Platform, Artikel → Bilder).

PostgreSQL

Der Industriestandard. Postgres in Docker ist ein Einzeiler, Prisma-Support ist erstklassig. JSON-Felder für flexible Daten, berechnete Spalten, exzellente Performance. Du kannst Views für Dashboard-Aggregationen nutzen. Backup ist ein pg_dump. Die sicherste Wahl.

Funktioniert gut wenn

  • Relationale Daten (Haul → Items)
  • Bester Prisma-Support
  • JSON-Felder für Flexibilität
  • Views für Dashboard-Queries

Achtung bei

  • Separater Docker-Container nötig
  • Etwas mehr RAM als SQLite

SQLite (via Prisma)

Next.js + Prisma
↓
SQLite (Datei)
↓
buy2sell.db
Maximale Einfachheit: Eine einzige Datei, kein separater DB-Container. Prisma unterstützt SQLite. Backup = Datei kopieren. Für dein Datenvolumen (hunderte bis tausende Artikel) mehr als ausreichend. Nachteil: Kein JSON-Feld-Support in Prisma/SQLite, keine Views, limitierte Concurrent Writes.

Funktioniert gut wenn

  • Maximale Einfachheit gewünscht
  • Ein Docker-Container für alles
  • Backup = Datei kopieren

Achtung bei

  • Kein JSON-Feld in Prisma/SQLite
  • Keine DB-Views
  • Concurrent Writes limitiert

Solide Alternative zu Postgres. Guter Prisma-Support, weit verbreitet, JSON-Support vorhanden. Kein technischer Vorteil gegenüber Postgres für deinen Use Case. MariaDB ist der Fork mit besserer Performance. Funktioniert, aber es gibt keinen Grund Postgres vorzuziehen.

Funktioniert gut wenn

  • Du MySQL schon kennst
  • Guter Prisma-Support
  • Bewährt und stabil

Achtung bei

  • Kein Vorteil vs. Postgres hier
  • Weniger Features als Postgres
  • Separater Container nötig

SQLite on Steroids: Turso ist managed libSQL mit Edge-Replicas. Aber: Braucht Drizzle statt Prisma (oder experimentellen Prisma-Adapter), ist ein externer Service (kein reines Self-Hosting), und für dein Volumen absoluter Overkill. Coole Technologie, falsche Stelle.

Funktioniert gut wenn

  • Edge-Performance wichtig wäre
  • Multi-Region-Replicas nötig

Achtung bei

  • Kein reines Self-Hosting
  • Prisma-Support experimentell
  • Overkill für den Use Case
  • Externe Abhängigkeit
